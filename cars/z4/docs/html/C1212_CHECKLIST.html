A position sensor has a distinct voltage per gate so reverse should be visible; a ratio-derived gear never could. THREE OUTCOMES. That is an M800 calibration fix rather than a dash one, and the gear tables are already decoded. (c) Gear reads 1: indistinguishable from first gear, which is the exact failure item 1 warns about. Protocol

  1. Always start from the same baseline copy of C1212 Alsense.c1212v64. Never chain edits.
  2. Give every field in a save a DIFFERENT value, so runs can be matched to fields by value.
  3. Write down what each field read BEFORE changing it — that is what decodes the field, not just locates it.
  4. Save As a new filename. Do not send to the dash.
  5. Run the diff after each save before moving on.

After each save:

python cars/z4/tools/diff_e35.py "cars/z4/source/C1212 Alsense.c1212v64" "cars/z4/source/<new>.c1212v64" --map formats/c1212_map.json --record "save 1 - display page"

Save 2 — CAN bus mode — the last frame-format question

Screens: CAN / communications

Partly done. REWRITTEN 2026-08-12, because BOTH halves of the original item were asking for the wrong thing, and the second half was wrong in the same way as the first. The RATE half landed (Alsense FlagTest.c1212v64): rate is not per-template at all but a bus-level option, one u16 at 0x111FCA, 1M = 1 and 500K = 2, now confirmed. The FRAME FORMAT half still asked for a template's standard/extended setting, and there is no such setting. A screenshot of the CAN 1 tab with the Mode dropdown open shows the format is decided at the BUS: Mode offers CAN or J1939, and J1939 is 29-bit extended by definition. So the remaining edit is a bus mode change and the field to watch is the candidate at 0x111FC8, not +0x1FB4. The whole item descended from one guess — that the template flag words carried direction, rate and frame format — and all three have now been found elsewhere, so nothing is left to ask of those words.

READING DONE 2026-08-12. It did NOT settle the field, but it killed the alternative. CAN 2 reads Mode CAN, Rate 1M - the same as CAN 1 - so no second enum position is named and an edit is still needed. What it settled is the LAYOUT: if 0x111FCC were CAN 2's mode, its value of 1 would have to mean J1939, and the screen says CAN. So 0x111FCC stays CAN 2 rate, the probable claim on it survives, and 0x111FCE (reads 0) becomes the best candidate for CAN 2's mode. Note the field ORDER that implies - mode, rate, rate, mode - is odd and unexplained, which is itself a reason to leave 0x111FC8 at candidate rather than promoting it on position alone. DO NOT LEAVE J1939 ON THE CAR — save it under the test name below and reload the real config before the dash is used, because J1939 on CAN 1 takes every device on that bus off the air.
