FileWhat it covers
00-multi-car-proposal.mdBuilt. One repo holding many cars, with parsers keyed to formats rather than cars — the argument for why this repo is shaped as it is, kept as written.
01-model-provenance.mdBuilt as model.py at the repo root. The normalised model carrying origin and confidence per field. Solves the design problem 00 raises.
02-tuning-history.mdWhat each of the twelve M800 calibrations changed in the fuel and ignition tables — lineage, the freeze since 2_1_25, and the Stroker404 discrepancy, answered: the car has the 3.4 stroker. source/m800-tunes/ holds 16 files; the other four are IO controlled edits that touch no table. Written the day the tables became readable, and carrying the 9 Aug merge review that cut the stroker merge to its off-idle fuel cells.

04-e35-inventory.mdGenerated by tools/e35_inventory.py from the file the car uses. Everything readable in the live calibration — identity, tables, fields, data sets, candidates — and the coverage figure saying how much of the file that is.
05-e35-terrain.mdGenerated by tools/e35_scan.py. The residue — every table-shaped structure that neither e35_map.json nor the exe's own schema accounts for. Offsets, shapes, value smells, tuned-vs-factory, and which screenshot would settle each. It excludes schema-typed records as well as mapped ones, so it is a short list now, not a survey of the unmapped bulk.
06-winemp-schema.mdECU Manager's own parameter table, mined out of WinEMP.exe and validated 12/12 against the repo's anchors — 575 clean typed structures (of 600 extracted) covering 58.6% of the calibration, named one screenshot at a time. formats/e35_schema.json is the data.
M800_CHECKLIST.mdGenerated from formats/e35_map.json. The controlled edits left to make in ECU Manager to finish the M800 IO map. Edit the JSON, not this.
C1212_CHECKLIST.mdGenerated from formats/c1212_map.json. Same, for the dash. The dash's IO and CAN are mapped; what remains is display paging, the template flag bits, and harvesting built-in channel ids. Only save 1 is worth a trip on its own.

Everything here also renders to html/ — one styled page per doc, built by render/docs.py, with html/index.html as the entry point. The .md files remain the source of truth. That renderer is shared: it belongs to no car and the M3's docs go through it too.

The pinout, the config audit and the offset maps currently all render into schematic/z4_pinout_schematic.html. Splitting the audit and the mapping method into separate numbered docs is the next structural step, once the dash pass lands.
