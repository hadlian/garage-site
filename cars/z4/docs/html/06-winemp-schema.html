The schema was in the tool all along — mining WinEMP.exe

Written 2026-08-09, the day the map stopped growing one screenshot at a time. The full result is formats/e35_schema.json.

The idea

ECU Manager draws every table screen, so it must know every table's offset, dimensions and encoding. The question was never whether WinEMP.exe contains the complete .e35 schema — it was whether the schema could be extracted safely. The repo got burned once by trusting documentation-shaped data (master.chl's channel names), and the rule since has been: no anchor, no name.

What changed is that this repo now holds twelve anchors — seven tables and five axes whose offsets, dimensions and encodings were proven from screenshots, logs and byte evidence. Twelve known answers are enough to validate an extracted schema instead of trusting it.

The find

Searching the binary for the twelve anchored offsets lit up a parameter table: 24-byte records, offset, cols, rows, min, max, f1, f2, at 0x34908C-0x34C3EC (one of several copies — the others describe other ECU models and older firmware layouts). The encoding formula fell out of the anchors:

scale = (f1 >> 8) / 10^(f2 & 0xFF) cell size = f2 >> 8 signed = min < 0

Read off two anchors, it predicted the other ten — including the odd x0.5 and x0.2 encodings that had each been established cell-by-cell. 12/12 anchors validate on offset, columns, cell size and scale.

What it settles immediately

  • Ign Main allocates 55x35, ending exactly at Injection Timing — the 55-column stride found empirically was the allocation, confirmed.
  • Injection Timing is 20x11, not 1-D: the long-mysterious 0x1FBA block ("10 ascending rows, owner unknown") is its rows 1-10. The map's oldest unowned structure, owned.
  • The comp tables allocate 26x11: the two "shadow" 6-row blocks at 0x2E24 and 0x2F42 are the unused rows 5-10 of Fuel AT and Fuel ET Comp. Two more mysteries closed by allocation arithmetic.
  • ~~Ign AT Comp lives at 0x2FDE~~ — withdrawn 2026-08-09. The schema typed a 26x11 ±10.0° region at 0x2FDE and this doc named it by plausibility — the exact move the anchors exist to prevent, and it was wrong: checklist save 7's controlled edit put Ign AT Comp at 0x4461. The 0x2FDE region stands typed and unnamed, like it should have all along.
  • Fuel Main allocates 40x24, Lambda 20x11, Accel Clamp 20x11.

What it deliberately does not do

The schema types 575 clean structures covering 58.6% of the file — shape, size, scale, limits — and names none of them. Names still come the way they always have: an ECU Manager screenshot of a named screen, matched to a typed region, one at a time — except now every screenshot lands on a prepared slot, and the min/max/scale come pre-validated.

The names are in the exe too, and they still don't bind

Tried 10 Aug 2026, and it fails. WinEMP.exe also carries ECU Manager's own name strings — every table name in menu order, Fuel MAP Comp through Ign 12 Indiv Trim. The obvious move is to bind the *N*th name to the *N*th record of the parameter table above and name several hundred records at once.

It does not work, and it fails in the most dangerous way: it is right until it isn't. Anchored on Ign AT Comp, the walk correctly names Ign ET Comp and Ign MAP Comp — three for three against controlled-edit anchors — and then gets the next four wrong, including 0x05265, which save 7 pinned as Gear Comp by controlled edit. The record table carries entries the name list does not (axes, and duplicate offsets), so the two walk out of step, and the per-family offset is not constant: measured deltas of 135, 242, 251 and 264.

One name did reach the map on this reasoning — 0x02FDE as Fuel FT Comp — and was retracted the same day. This is the aux "list position" rule wearing a new hat: a run of coincidental agreement mistaken for a rule. What saved it was testing the method against anchors it hadn't used.

What survives is a vocabulary, formats/e35_names.json, mined by tools/winemp_names.py: which tables exist and their exact spellings, with no offsets attached and a warning against attaching any. That is genuinely useful for the work that remains — it says which screens are worth a screenshot, and lets one be matched by exact string rather than by eye.

The channel list is in there too, and is a different revision from the id space the .e35 uses: it inserts Vertical G Force at id 17 and expands the two obsolete Exhaust Temp entries into eight. It matches the repo's Z4.cml anchors at ids 1, 3, 4, 5, 6 and disagrees at 26. That confirms the standing note that the two lists stop agreeing — and sharpens it, because the divergence starts at id 17, not "roughly 26"; the anchors just don't sample in between.

25 extracted records are flagged conflicts_anchor: they collide with anchor-proven spans and describe an older firmware's layout of the same addresses (a 40x21 ignition table at 0x1072, for instance). The exe supports many ECU versions; the anchors say which records are this car's.

What's next for full coverage

  1. Teach the reader to serve any schema record by offset (typed, unnamed).
  2. Walk the named screens against the typed regions — each screenshot now fills a slot instead of hunting for one.
  3. The remaining ~41% of the file is mostly the IO/comms region the checklist saves cover, smaller record families the extraction window may have missed, and genuine padding. A second mining pass for the axis-to- table linkage (which axis record belongs to which table record — the exe must know that too) would retire the last "which copy" ambiguities.
