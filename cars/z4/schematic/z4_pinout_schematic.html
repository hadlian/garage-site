Findings

CRIT · 2 output(s) are enabled with no trigger at all

pin 6 “ABS power 40/2” (25 A), pin 7 “ABS power 25” (25 A). The condition array is empty — not a constant zero, no operations whatsoever — so these can never energise. Pin 5 “ABS power 40/1”, the sister feed, does have logic.

→ Bind a trigger, or remove the channel so the pin does not read as a live feed on the layout sheet.

WARN · CAN channel CDL3.Diff temp is received but never used

It is decoded off 0x118 alongside RPM and engine temp, and no condition or output references it. The diff pump runs purely on ignition + RPM ≥ 1.

→ Either gate the diff pump on diff temperature — which is presumably why the channel is decoded — or drop the channel.

WARN · Fuel pump 1 and fuel pump 2 do not have symmetrical logic

fuel pump1 has a third OR group (ign sw is OFF AND “fuel pump 1 & 2 pause” toggled) that fuel pump2 does not. On the shared-pump selection both run; on the pause path only pump 1 does.

→ Confirm this is deliberate. If the pause path is meant to keep pressure up with the key off, one pump doing it and not the other is a surprising split.

WARN · Dash: 1 short name is used by more than one channel

“LFTP” is on LF Tire Pressure and RF Tire Pressure. The short name is what appears on the dash and in the log tree, so two channels are indistinguishable wherever it is used.

→ Rename the duplicate in the C1212 config. Check the sensor is on the corner the long name claims before assuming it is only a labelling slip.

INFO · Motor and pump outputs carry no inductive-load flag in this file

blower, diff pump, fan1, fan2, fuel pump1, fuel pump2, spare pumps 1/2/3, spare pumps 4/5/6, starter, wiper. The PDM config schema exposes no such field, unlike the AiM PDM32 on the Ravin car — noted here only so the comparison is not read as a missing setting.

→ Nothing to change in the config. Verify clamping is handled by the PDM hardware for these channels.

INFO · No output uses StayAlive, MasterShutdown, AlwaysRetry or LinkedOutput

All 29 outputs leave the four flags clear, and the MasterRetry / MasterShutdown channels at the top of OutputPins are both empty.

→ Expected on a simple car. Worth a second look for the fuel pumps and the ECU feed, which are the usual StayAlive candidates.

INFO · Output pin index 15 is absent from the file

The array holds 29 outputs, indices 0–29 with 15 missing entirely — not present and disabled, but not written.

→ Normal if that pin does not exist on this PDM variant. Confirm against the hardware pinout before anyone plans to use it.

INFO · The PDM's “CDL3” channels are fed by the C1212, not by a CDL3

Every channel the PDM decodes off 0x118 is named CDL3.something, but the dash in this car is a C1212. Decoding the dash's own template ids settles it: "Transmitt to PDM" transmits on 0x118, which is exactly an id the PDM listens on. The C1212 is the source; the CDL3 names are stale labels carried over from a previous dash.

→ Rename the PDM channels from CDL3.* to something that names the C1212, so the next person reading that config is not looking for a dash the car does not have.

INFO · Dash: 38 of 63 pin objects carry no calibration

device 1: 16 of 35; device 2: 22 of 28. An uncalibrated pin is unconfigured, so this is the spare capacity in the logging hardware as the config stands.

→ Nothing to fix. Useful when the next sensor needs somewhere to go — and worth checking against the harness, since a wired-but-uncalibrated pin reads as a dead channel.

CAN message layouts

Which channel sits in which byte, decoded. Each template holds a 0x1E-stride record array at +0x00EA: word 0 is the byte position in the message, word 9 the source channel on a transmit template and word 13 the destination on a receive one, with exactly one of the two populated. It was located against a known answer rather than guessed — the PDM’s XML states it reads 0x118 as RPM at byte 0, engine temp at byte 2 and diff temp at byte 4, and those three channel ids sit exactly there. Three independent checks agree: Speed Sensors falls out as Wheel Speed FL/FR/RL/RR on bytes 0/2/4/6 with nothing fitted to it; FL_Temps_1 resolves to FL Ch1–Ch3, matching its own name; and MoTeC M800 (V3.3+) Set 1 puts ids 3, 4, 5 and 6 on bytes 2, 4, 6 and 8, which is where MoTeC’s published Set 1 layout has manifold pressure, air temperature, engine temperature and lambda 1. Ids resolve against the dash’s own channel records first and the M800 anchor list second — the two devices share the id space. Ids with neither are shown bare.
The PDM reads a byte the dash never writes. CDL3.Reverse Gear is read from 0x118 byte 6. The dash’s transmit template for that id binds a channel to byte 0, byte 2, byte 4 and to nothing else, so that input can only ever read whatever the message pads with.
