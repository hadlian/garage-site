Resolved 14 Aug 2026, and not the way the report suggests. The owner confirms the
car starts and runs today, and that M1 Tune was online with the engine running
when this was captured. Those two facts cannot both hold alongside the map above: an
inline six does not run on four ignition outputs, and it does not run on fuel routed to
four peak-hold pins the loom leaves unwired. So whatever the connection state,
the report does not describe the calibration the engine is running on.
The likeliest mechanism is that it was produced from the package open in the workspace
rather than from the device — the capture came from the Open Package dialog, which is
the local library, and being online does not make a report about the loaded package
into a report about the ECU. That is a claim about M1 Tune's behaviour, not something
this repo can verify.
A decode attempt the same day rules out one shortcut. The TuneConfig gives 140 IO
resource parameters a real address, but nothing sits at those addresses in any readable
payload — the values are in the encrypted section formats/m1pkg_map.json documents.
M1 Tune decrypts its own format, so it will happily show these bindings from the
package alone. **A report out of M1 Tune is therefore not, on its own, evidence about
the ECU** — which is the trap this whole document exists to describe, hit a second time
by a different route.
What would actually settle it: with M1 Tune online, save the calibration *from the
ECU* to a new package and send that file. Then it can be diffed against the one in
source/, and a difference is proof of provenance in a way a report is not.

2. Safety hazards if this is powered up or cranked

Ranked by real-world severity.

  1. Injectors driven by static on/off functions — the genuinely dangerous one. Coolant Fan 1 → INJ LS2 (= Injector 2), ECU Power Relay → INJ LS3 (= Injector 3), Fuel Pump Main → INJ LS4 (= Injector 4), Warning Light → INJ LS6 (= Injector 6). Each grounds an injector continuously whenever the function is on. Raw fuel into the cylinder → hydrolock, bore wash, oil dilution, fire. Nothing in the ECU protects against this — these are valid output assignments as far as M1 is concerned.
  2. Cylinders 5 and 6 have no spark and no injection. Ignition Cylinder 5/6 and Fuel Cylinder 5/6 are all Not in Use. Combined with item 1, unburnt fuel can reach the exhaust.
  3. No oil pressure protection. Engine Oil Pressure Sensor = Not in Use, though the sensor is wired on A4 (AV16).
  4. Throttle servo motor on the wrong bridge. Motor Output → Bridge Output 1 (HB1/HB2); HB2 is the compressor relay. Commanding throttle would drive the compressor relay output.
  5. Throttle pedal and servo read from unrelated sensors — Pedal Main → AV3 (= Gear Position 1), Pedal Tracking → AV2 (= Steering Angle); Servo Pos Main → AV4 (= Gear Position 2), Tracking → AV5 (= ECT pressure).

Correction to an earlier assessment: this is a "will not work" fault, not a runaway-throttle risk. M1 continuously cross-checks Main against Tracking on both the pedal and the servo. Gear position and steering angle will never track each other, so the implausibility check should fault immediately and disable throttle control. That check is doing its job — but it means the DBW system is inoperable, not that it is safe to run.

5. Recommended path

  1. Do not crank. Treat the current file as unsafe to run.
  2. Start from a correct base: obtain/build a 6-cylinder GPR Pro configuration. Confirm whether the target is S52 or S54 — cam control and VANOS strategy differ substantially.
  3. Re-pin the whole resource map against RMod REV 01 in one deliberate pass, Engine tab then Vehicle tab. Patching individual rows will leave silent mismatches.
  4. Resolve the HB4/HB5/HB6 off-by-one on the KMP valves — either the harness doc is one pin off or the config is. Two-minute output test.
  5. Confirm VANOS wiring (HB3 / C31) — assigned in software, blank in the harness doc.
  6. Bench-test before first start: output test every driver with injectors and coils disconnected; verify each analogue input reads its intended sensor; confirm crank/cam sync; verify oil pressure reads before enabling any run condition.
  7. Only then revisit the PDM-side items (inverted PCM12Vpwr2 feed, CAN3 termination, PDM ECU protocol match).
