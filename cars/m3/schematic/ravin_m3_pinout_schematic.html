Two confirmed faults are marked in red below. PDM Grey 24/25 feeds MoTeC / coil / injector / VSS but its output is configured to switch on when ignition is OFF — the inverse of the identical feeds on Grey 1/2 and Black 6/7. PDM Black 12/23 drives the headlights at 20 A but its trigger is hard-coded to constant zero, so the output can never turn on.
Amber rows are items to verify. CAN3 (ECU ↔ PDM) is terminated only at the AiM end · CAN 2 accessories are fed from two sources · brake/tail output is permanently on · the transponder feed is missing from the layout sheet · keypad K11 “Compressor power” is not referenced by any output.

An M1 package carries firmware only — the strategy and its table definitions — so it says what this ECU can do, not what it has been configured to do. The resource assignments are not in it and are not recoverable from any file on this car.
No calibration loaded. Fill in ecu/resources.json — map each M1 resource name to the function the calibration assigns it — then re-run build.py. The M150 tables gain an ECU column and every wired-but-unassigned or assigned-but-unwired pin is listed here automatically. The 333 assignable functions this firmware exposes are listed under functions.bound, parsed out of the package rather than typed, across 35 groups (Air Conditioner, Airbox, Alternative Fuel, …). That is the screen you read in M1 Tune, so filling that side and inverting it is less error-prone than working from the resource names. 0 of them are filled in.
